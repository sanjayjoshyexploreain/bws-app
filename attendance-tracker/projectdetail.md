# B&W Attendance Tracker - Project Documentation

## Project Overview
The B&W Attendance Tracker is a Progressive Web Application (PWA) built specifically for B&W Services. It serves two main user roles: 
1. **Workers**: Can log their daily site attendance, upload site photos, view their own past entries, and request workwear.
2. **Admins/Managers**: Can review all worker entries, approve/reject entries, view monthly reports, and generate 4-digit access PINs.

The application relies entirely on Microsoft Power Automate flows and SharePoint lists as its backend database and API layer. This serverless architecture ensures zero hosting costs for backend infrastructure.

---

## Technology Stack
- **Frontend Framework**: React (Vite)
- **Routing**: React Router DOM (v6)
- **Styling**: Vanilla CSS (`App.css`, `index.css`) with CSS Variables for a dynamic, modern "dark mode" design system.
- **Backend/API**: Microsoft Power Automate (HTTP Webhook Triggers)
- **Database**: Microsoft SharePoint Lists
- **Deployment**: Hostinger (Static files served via Apache with `.htaccess` rewrite rules for SPA routing)
- **PWA Capabilities**: Service Workers (`sw.js`) and Web Manifest (`manifest.json`) for installability on mobile devices.

---

## Core Architecture & Patterns

### 1. Authentication & Security
- **No Passwords Stored**: Workers log in using their exact Full Name and a 4-digit PIN generated by an admin.
- **Hidden Admin Route**: The admin login portal is completely hidden from regular workers. An admin must first visit a secret route (`/bws-admin`) to set a `sessionStorage` flag. Only then does the application render the Admin OTP login screen.
- **OTP (One-Time Password) Login**: Admins do not use static passwords. They click a button to generate an OTP which is emailed to them via Power Automate. They use this OTP to authenticate securely.
- **Failsafe Name Matching**: When users log in, the app automatically strips all spaces from their input and converts it to uppercase. The backend Power Automate flow does the same, ensuring that accidental double-spaces or typos don't block access.
- **Session Timeout**: The app enforces a strict 1-hour session limit to prevent unauthorized access on shared devices.

### 2. API Layer (`src/api/api.js`)
All backend interactions are abstracted into an `Api` object. Every function makes a POST request to a specific Power Automate flow webhook URL with the required JSON payload.

## Key Features

### Worker Workflows
1. **Submit Entry**: Workers select their Site, Area, Activity, Status (In/Out/Absent), and Date.
2. **Photo Upload**: Workers can upload multiple compressed images (resized via HTML Canvas in the browser before upload to save bandwidth) directly to SharePoint as list attachments.
3. **History View**: Workers can browse their own past entries sorted by month.
4. **Workwear Requests**: Workers can order safety gear (boots, gloves, goggles) specifying sizes and quantities.

### Admin Workflows
1. **Dashboard & Moderation**: Admins see a live feed of all "Pending" entries. They can review the details, view attached photos, add Admin Notes, and mark the entry as "Approved" or "Rejected".
2. **Access PIN Generation**: A batch utility tool that scans the employee list and generates secure 4-digit PINs (with a 300ms delay between API calls to respect Power Automate rate limits) for employees who are missing one.
3. **Monthly Reports**: Admins can generate aggregate reports for any given month, calculate total hours/days worked per employee, and export the data.

## Power Automate Integration Guidelines
When building a similar app, the backend logic must be offloaded to Power Automate flows:
- **Triggers**: Use the *When an HTTP request is received* trigger.
- **Responses**: Use the *Response* action to send JSON back to the app (e.g., `{ "success": true, "data": ... }`).
- **Data Operations**: Use the *Filter array* action for complex string manipulation (like removing spaces) since OData filters in the *Get items* step have limitations.
- **CORS**: Ensure your Power Automate flows don't have restrictive CORS policies, or handle them via custom response headers if accessed cross-origin.
